# v0.2.0の設計

設計レビューで確定した仕様を記録する。実装・リリースは未実施。

## 対象

`fare <FROM> <TO>`、`pass <FROM> <TO>`、`delay-cert` を追加する。既存コマンド、JSON Envelopeの `schema_version: 1`、終了コード、グローバルオプション、キャッシュの契約は維持する。

普通運賃と定期券料金には料金検索専用の駅マスター・経路データを使い、既存の経路検索・地下鉄時刻表のIDは流用しない。料金経路は既定ですべて返し、先頭・最安を最短や推奨と意味付けしない。定期券料金から購入資格を判定せず、延着証明書から現在の運行状況を推測しない。

## 料金検索で確定した判断

- 有効な両駅の間に料金経路の対応がない場合は、正常な0件とする。同駅間でも0円を補わない。[ADR-0006](adr/0006-return-empty-results-for-unavailable-fare-routes.md)
- 普通運賃の欠落・不正は `fare_yen: null` として経路を残し、終了コード5の部分失敗とする。[ADR-0004](adr/0004-report-partial-results-as-errors.md)
- 定期料金の取得失敗は `types: []` として経路を残す。全料金区分が失敗しても取得済み経路を保持する。[ADR-0004](adr/0004-report-partial-results-as-errors.md)
- `--type` は全経路の券種名から一度だけ解決する。候補が不完全な場合は、確認できた完全一致だけを使い、部分一致や未発見の断定をしない。[ADR-0007](adr/0007-resolve-pass-types-across-fare-routes.md)
- `--with-bus` の区分対応がない経路は `types: []` と `not_found` の部分失敗とし、通常区分には戻さない。[ADR-0004](adr/0004-report-partial-results-as-errors.md)
- 定期料金の一期間が欠落・不正な場合は、その期間だけを `prices` から除外し、券種名と正常な期間の料金を保持する。全期間が不正でも券種名は `prices: []` として残す。終了コード5の部分失敗とする。[ADR-0004](adr/0004-report-partial-results-as-errors.md)

## 延着証明書の路線指定

`--line` は既知の地下鉄路線名とAPI内の路線名を合わせ、同一名の重複を除いて名前解決する。既知名は東山線、名城線・名港線、鶴舞線、桜通線、上飯田線とする。前後空白除去とNFKC正規化後の完全一致を優先し、完全一致がなければ部分一致を使い、複数候補は `ambiguous` とする。

「名城線」「名港線」は「名城線・名港線」に部分一致する。公開データの路線名は「名城線・名港線」を維持し、証明書を二路線分に複製しない。有効な路線で証明書が0件の場合は、`certificates: []`、`complete: true`、終了コード0とする。証明書の取得・解析失敗を正常な0件として扱わない。

証明対象日時が欠落・不正な証明書は除外し、正常な証明書を保持して日時の降順に並べる。全件の日時が不正な場合も空の一覧とエラーを返し、`complete: false`、終了コード5とする。[ADR-0004](adr/0004-report-partial-results-as-errors.md)

## コマンドと名前解決

```text
nkotsu fare [OPTIONS] <FROM> <TO>
  --route <ROUTE>

nkotsu pass [OPTIONS] <FROM> <TO>
  --route <ROUTE>
  --type <TYPE>
  --months <MONTHS>    1 / 3 / 6
  --with-bus

nkotsu delay-cert [OPTIONS]
  --line <LINE>
  --date <YYYY-MM-DD>
  --limit <N>          1以上、省略時は全件
```

FROM・TO・経路名・券種名・路線名は、前後空白除去とNFKC正規化後の完全一致を優先し、完全一致がなければ部分一致を使う。複数候補を自動選択せず `ambiguous`、対象なしは `not_found`、どちらも終了コード3とする。券種候補が不完全な場合だけは、上記ADR-0007の例外に従う。

`--route` による経路選択後の券種を `--type` の候補にする。券種を固定enumにせず、APIの券種名を使う。`--months` は料金の表示対象を指定する。`--date` は実在する暦日の `YYYY-MM-DD` とし、不正な引数は `invalid_arguments`、終了コード2とする。延着証明書は路線・日付で絞り、証明対象日時の降順に並べた後に `--limit` を適用する。

## データ取得とキャッシュ

料金データの基点は `https://www.kotsu.city.nagoya.jp/STATION_DATA/teiki/` とする。

| データ | 用途 |
| --- | --- |
| `station.json` | 料金検索用の駅名と駅ID |
| `ends/{fromId}.json` | 到着駅IDから料金経路セットIDへの対応 |
| `route/{routeSetId}.json` | 料金経路名、普通運賃FARE、定期料金区分TEIKI |
| `teiki/{fareClassId}.json` | 券種名と1・3・6か月料金 |
| `use_shi_bus.json` | `--with-bus` の場合だけ使用する料金区分変換 |

`fare` と `pass` の駅解決・経路取得は `api::teiki` の共通処理にまとめ、HTTP処理を複製しない。既存クライアントのURL単位の重複排除と最大同時HTTP数4を使う。静的データの既定TTLは24時間とし、ETag・Last-Modified・Cache-Control、`--refresh`、`--no-cache` は既存実装の契約に従う。期限切れデータへの失敗時フォールバックは追加しない。

延着証明書は `https://www.kotsu.city.nagoya.jp/datas/traffic_delay_certificate.json` を毎回取得し、永続キャッシュしない。`delay_id`、`rosen_name`、`sort_no`、`delay_datetime`、`title`、`max_delay_time` を入力とし、並べ替えにAPI順や `sort_no` の意味を仮定しない。

内部IDはすべて文字列として保持し、正規化済みJSONには原則露出させない。`DISTANCE` は公開モデルに追加しない。延着時間は「10分」「60分以上」などの文字列を保持する。証明書URLは `https://www.kotsu.city.nagoya.jp/rp/subway/delay_certificate.html?delay_id=<ID>` とする。

## 正規化済みJSONとraw

`Data` に `Fare(FareResult)`、`Pass(PassResult)`、`DelayCertificates(DelayCertificates)` を追加する。既存variantのJSON構造は変更しない。

| モデル | 公開フィールド |
| --- | --- |
| `FareResult` | `from: String`, `to: String`, `routes: Vec<FareRoute>` |
| `FareRoute` | `name: String`, `fare_yen: Option<u32>` |
| `PassResult` | `from: String`, `to: String`, `routes: Vec<PassRoute>` |
| `PassRoute` | `name: String`, `types: Vec<PassType>` |
| `PassType` | `name: String`, `prices: Vec<PassPrice>` |
| `PassPrice` | `months: u8`, `yen: u32` |
| `DelayCertificates` | `fetched_at: String`, `certificates: Vec<DelayCertificate>` |
| `DelayCertificate` | `line: String`, `date: String`, `title: String`, `max_delay_time: String`, `url: String` |

`date` は証明対象の暦日を `YYYY-MM-DD` で返す。取得日時と証明対象日時を区別する。購入資格を表す `eligible` などの項目は生成しない。

全コマンドで既存Envelopeの `schema_version: 1`、`complete`、`data`、`errors` を維持する。各エラーは既存の `scope`、`code`、`exit_code`、`message` を持つ。新しいエラーコードは追加せず、部分失敗は失敗範囲を記録して非0で終了する。複数エラー時の終了コードは既存どおり数値最大とする。料金経路セットなどの共通前提の取得失敗は `data: null` の全体失敗とする。

`--raw` は取得した本文をURLごとの文字列で返し、JSONへの再解析や本文の空白・改行・BOMの変更をしない。同じURLを重複取得しない。失敗時の取得済み本文も既存クライアントの仕組みで保持する。料金検索に必要なstation・ends・route、定期券検索ではteikiと必要なuse_shi_bus、証明書では一覧APIの本文が対象となる。

## Human出力

- `fare`: 出発駅→到着駅、各経路名、普通運賃を表示する。経路を番号付きで表示してよい。普通運賃昇順・経路名順の安定ソートを許容し、不明な運賃を最安と扱わない。正常な0件は「該当する運賃経路はありません」と表示する。
- `pass`: 出発駅→到着駅、各経路名、対象券種、対象期間の料金を表示する。既定はすべての券種・期間。通常のHuman出力には「※表示料金は料金データに基づくもので、購入資格を保証しません。」を表示する。`--quiet` での省略は許容するが、結果・エラー・欠落警告は既存どおり維持する。
- `delay-cert`: 証明対象日、路線、タイトル、文字列の最大遅延、証明書URLを表示する。複数件は番号付きでよい。現在の遅延・平常運行・列車位置は推測せず、現在状態の確認は `status` に委ねる。

## Help・ドキュメント・Skill

トップレベルhelpに新3コマンドを追加する。`fare --help` は取得対象・複数経路・最初の経路を最短と扱わないこと・実行例・内蔵docsへの導線を含める。`pass --help` は購入資格を判定しないこと・全オプション・内蔵docsへの導線を含める。`delay-cert --help` には「現在の遅延状況ではありません。」と明記する。

`docs/cli/fare.md`、`pass.md`、`delay-cert.md` を追加し、内蔵docsを `bus`、`subway`、`route`、`fare`、`pass`、`delay-cert`、`output`、`troubleshooting` の8件にする。`src/docs.rs`、help・docsテスト、Release workflowの5件検査を8件に更新する。

利用者向けSkillのコマンド表・対応範囲に新3コマンドを追加し、詳細は各 `nkotsu docs show` に誘導する。延着証明書を現在の遅延情報と解釈しないことを明記する。READMEに3機能を追加し、次の段階とする記述を更新する。`docs/cli-behavior.md` の対象機能・内蔵docsの説明も実装時に整合させる。

## 検証と完了条件

既存テストの仕組みを使い、次を確認する。

- `fare`: 専用駅IDのFROM/TO解決、NFKC、endsとroute、普通運賃、全経路、先頭を最短と扱わないこと、`--route`、正常0件、運賃欠損・不正、JSON、raw、キャッシュ。
- `pass`: TEIKI、同一区分の取得重複排除、複数経路・券種、`--type` の全経路共通解決と不完全な候補、`--months` 1/3/6、`--with-bus` と対応なし、価格欠損・不正、部分取得失敗・全区分失敗、JSON、raw。

- 新3コマンドのhelpとdocs、内蔵docs8件、既存コマンド・JSONの回帰がないこと。

大学生料金6440/18360/34780のfixtureは、公式の5区の料金に対応する。藤が丘→名古屋の東山線単独経路は4区の6200/17670/33480であり、このfixtureを全経路に共通の料金と扱わない。

## 実装順序とリリース

共通の料金API層→fare→pass→delay-cert→出力→help/docs→Skill/README→統合テスト→Release workflowの順で実装する。実装完了後、Cargo.tomlとCargo.lockのバージョンを0.2.0に揃える。

リリース時は既存workflowを使い、CI、crates.io、macOS Intel・Apple Silicon、Linux x86_64・ARM64、Windows x86_64、SHA256SUMS、GitHub Releaseを対象とする。タグ `v0.2.0` の作成・pushを含む公開操作は別の実行工程とする。
