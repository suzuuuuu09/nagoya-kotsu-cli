# 完全一致でも曖昧な経路検索の地点は選択しない

名前は前後空白除去とUnicode NFKC正規化の後、完全一致を優先し、完全一致候補がなければ部分一致で検索する。完全一致であっても候補が複数なら、候補を表示してエラーにする。地下鉄を暗黙に優先する規則は追加しない。

公式候補データには「藤が丘」の市バス停と地下鉄駅があり、名前だけでは交通施設を一意に選べない。`route --subway` では出発地と到着地の候補を地下鉄駅に絞って名前解決する。基本使用例とv0.1.0の完成条件の経路検索は、`nkotsu route 藤が丘 名古屋 --subway` に変更する。

指定なしの使用例を維持するために地下鉄を優先すると、同名の市バス停を意図した利用者の要求と異なる地点を選ぶおそれがある。曖昧な候補を勝手に決定しない方針を守り、利用者が交通手段を明示できる操作を採用する。

経路検索の交通手段指定は、地点候補と経路の乗車区間の両方に適用する。無指定では市バスと地下鉄の両方、`--bus` だけなら市バスのみ、`--subway` だけなら地下鉄のみ、両方指定なら市バスと地下鉄の両方を対象にする。地点候補だけを制限する方法では、地下鉄を指定しても途中に市バスの乗車区間を含む経路が返り得るため、経路全体にも指定を適用する。
