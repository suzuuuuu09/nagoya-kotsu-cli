# 独立した取得の一部が失敗した場合は結果と欠落を返す

`bus live` の系統別取得など、独立した複数の情報の取得で一部が失敗した場合は、成功した結果を表示し、取得できなかった範囲も明示する。正規化済みJSONにも結果が不完全であることを含め、終了コードは失敗の分類に対応する非0とする。

全結果を破棄する方法では取得できた情報まで利用できず、正常終了にする方法では取得失敗を情報が存在しない状態と取り違えるおそれがある。部分結果は利用可能にしつつ、不完全さと失敗を人間とプログラムの双方へ伝える。失敗した取得を空の成功結果として扱わない。

## 普通運賃の欠落・不正

`fare` で料金経路を取得できても普通運賃が欠落・不正な場合は、その経路を残して `fare_yen: null` とし、該当範囲のエラーを返す。`complete: false`、終了コード5とし、取得できた他の経路の運賃は保持する。運賃不明を正常な0件や0円として扱わず、既存の `invalid_response` / `parse_error` の分類を使う。v0.1.0の既存コマンドの扱いは変更しない。

## 定期券料金の取得失敗

`pass` で料金経路を取得できても対応する定期料金データの取得に失敗した場合は、その経路を `types: []` で残し、料金を取得できなかった範囲を `errors` に記録する。全料金区分の取得が失敗した場合も取得済みの経路を保持し、`data: null` や正常な0件に置き換えない。

`complete: false` とし、終了コードは既存の失敗分類に従う。取得できた他の区分の券種・料金は保持する。料金経路自体を取得できない場合は、コマンド全体の失敗として扱う。

`pass --with-bus` で市バス併用区分への対応がない場合も、対象経路を `types: []` で残し、該当範囲の `not_found` を記録する。対応がある経路の市バス併用料金は保持し、通常区分にはフォールバックしない。全区分に対応がない場合も経路は残し、`complete: false`、終了コード3とする。複数種別の失敗がある場合の終了コードは既存の集約規則に従う。

定期料金データを取得できても一期間の料金が欠落・不正な場合は、その期間だけを `prices` から除外し、券種名と正常な他の期間の料金を保持する。該当範囲のエラーを記録し、`complete: false`、終了コード5とする。全期間が欠落・不正な券種も `prices: []` として残し、料金を推測して補ったり0円に置き換えたりしない。

## 延着証明書の日時の欠落・不正

`delay-cert` で証明対象日時を解析できない証明書は正規化済み一覧から除外し、該当証明書のエラーを記録する。正常な証明書は保持して証明対象日時の降順に並べ、`complete: false`、終了コード5の部分失敗とする。全件の日時が不正な場合も `certificates: []` とエラーを返し、`data: null` や正常な0件に置き換えない。解析できない日時を推測して補わない。
