# 定期券料金

`pass <FROM> <TO>` は料金経路ごとの定期券料金を取得します。取得するのは料金データだけであり、利用者の通学証明や発売条件を確認しないため、表示料金は購入資格を保証しません。

```sh
nkotsu pass 藤が丘 名古屋
nkotsu pass 藤が丘 名古屋 --type 大学生 --months 1
nkotsu pass 藤が丘 名古屋 --with-bus --json
```

地点入力は駅名または地下鉄の完全修飾名を使えます。検索で選んだ `qualified_name` はそのまま渡せ、完全修飾名は正規化後の完全一致だけで解決します。市バスの完全修飾名は引数エラーです（`pass --with-bus` も駅の種別を変えません）。駅記号は表示用で、地点指定には使えません。

## 検索条件

| オプション | 指定すると変わる内容 |
| --- | --- |
| `--route <ROUTE>` | 料金経路名で絞り込む |
| `--type <TYPE>` | APIの券種名で絞り込む。固定された券種一覧ではない |
| `--months <MONTHS>` | 1・3・6か月のうち指定期間だけを表示する |
| `--with-bus` | 市バス併用用の定期料金区分を使用する |

駅と経路の名前解決は `fare` と共通です。既定ではすべての料金経路・券種・期間を表示します。両駅が有効でも料金経路がなければ、正常な0件として終了します。掲載順だけでは最短・推奨とする根拠にならないため、先頭の経路をそのようには扱いません。

`--type` の券種名は、対象となる全経路から候補を集め、前後の空白を除去してNFKC正規化し、一度だけ名前解決します。完全一致を優先し、完全一致がなければ部分一致を使います。複数候補は `ambiguous`、一致する候補がなければ `not_found` を返し、どちらも終了コード3で終了します。例えば「大学生」は「学生定期券（大学生）」への部分一致として使えます。

## 部分失敗

同じ料金区分は一度だけ取得します。一部の取得が失敗しても正常な料金を保持し、料金を取得できなかった経路は `types: []` で残します。全区分の取得が失敗した場合も経路を残します。

`--with-bus` の区分対応がない場合は、対象経路を `types: []` で残し、`not_found` を記録します。通常区分に戻すと、市バス併用を指定した検索条件と異なる料金を表示するため、フォールバックはしません。

一期間の料金が欠落・不正なら、その期間だけを `prices` から除外します。正常な期間と券種名を残し、全期間が不正でも券種名を `prices: []` で残します。

一部の券種候補を取得できなかった場合、`--type` には確認できた完全一致だけを使用します。完全一致がなければ、全経路を `types: []` で残します。未取得の候補によって検索結果が変わる可能性があるため、部分一致では選ばず、`not_found` とも断定しません。具体的な券種名を指定するか、取得失敗を解消して再実行してください。

部分失敗では `complete: false` と失敗した範囲を返し、非0の終了コードで終了します。料金の欠落・不正は終了コード5です。料金経路セット自体を取得できない場合は全体失敗になります。

## 出力

`--json` の `data` は `from`、`to`、`routes` を持ちます。経路の `types` に券種名 `name` と料金一覧 `prices` があり、各料金は `months` と `yen` を持ちます。内部IDや購入資格を表す項目は含みません。

通常の表示（Human出力）には、購入資格を保証しない旨の注意を添えます。`--quiet` でこの注意を省略しても結果・エラー・欠落警告は残します。`--json` に注意文は含めません。

`--raw` は料金検索に使った駅マスター・到着駅対応・経路セット・定期料金の本文を、取得URLごとの文字列で返します。市バス併用区分対応は、検索に使った場合だけ含めます。

料金データの既定キャッシュ期間は24時間です。共通の出力・キャッシュ仕様は `nkotsu docs show output` を参照してください。
