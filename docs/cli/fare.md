# 普通運賃

`fare <FROM> <TO>` は、料金検索専用の駅マスターと経路データから駅間の普通運賃を取得します。出発時刻や乗換条件を指定して経路を探す場合は、`route` を使ってください。

```sh
nkotsu fare 藤が丘 名古屋
nkotsu fare 藤が丘 名古屋 --json
nkotsu fare 藤が丘 名古屋 --route 東山線
```

地点入力は駅名または地下鉄の完全修飾名を使えます。検索で選んだ `qualified_name` はそのまま渡せ、完全修飾名は正規化後の完全一致だけで解決します。市バスの完全修飾名は引数エラーです（`pass --with-bus` も駅の種別を変えません）。駅記号は表示用で、地点指定には使えません。

## 駅と料金経路

駅名と料金経路名は、前後の空白を除去してNFKC正規化し、完全一致を優先して検索します。完全一致がなければ部分一致を使います。駅名の候補には料金検索専用のマスターを使います。同名の他社施設には路線名が付いている場合があります。

既定では料金経路をすべて返します。`--route <ROUTE>` を指定すると、経路名で絞り込みます。駅や経路の候補が複数なら `ambiguous`、一致する候補がなければ `not_found` を返し、どちらも終了コード3で終了します。

経路の掲載順や運賃は、最短・通常・推奨経路であることを示しません。そのため、先頭の経路や最安の経路をそのようには扱いません。

両駅が存在しても料金経路が提供されていなければ、正常な0件として終了コード0を返します。同駅間も0円とは推測しません。

## 出力と欠落

`--json` の `data` は `from`、`to`、`routes` を持ち、各経路は `name` と `fare_yen` を持ちます。内部の駅ID・料金区分ID・距離は含みません。

普通運賃が欠落・不正な経路は `fare_yen: null` で残し、他の経路の正常な運賃も保持します。この場合は `complete: false`、終了コード5とし、`errors` に欠落・不正の範囲を返します。

`--raw` は駅マスター・到着駅対応・経路セットの取得URLごとに、本文を文字列として返します。

静的料金データの既定キャッシュ期間は24時間です。再検証には `--refresh`、永続キャッシュの読み書きを無効化するには `--no-cache` を指定します。出力とキャッシュの詳細は `nkotsu docs show output` を参照してください。
