# トラブルシューティング

失敗した場合は、エラーメッセージと終了コードを確認してください。`--json` を指定した場合は、`errors` に含まれる `code` でエラー種別を判定できます。詳しい診断を調べるには `--verbose` を使います。

```sh
nkotsu docs list
nkotsu bus stop 上社 --no-cache --verbose
nkotsu route 藤が丘 名古屋 --subway --json
```

## 入力と候補の確認

`invalid_arguments` は、必須引数の不足、指定値の誤り、オプションの競合などを示します。サブコマンドの `--help` で指定方法を確認してください。`--json` と `--raw`、`--verbose` と `--quiet` は同時指定できません。docsでは `--raw` を使用できません。

`not_found` の場合は、入力した名前や系統、のりば、路線、方面を確認し、提示された候補を指定してください。内蔵ドキュメントの名前は `bus`、`subway`、`route`、`output`、`troubleshooting` です。

一方、`ambiguous` は候補が複数あることを示します。CLIは候補を自動選択しないため、より具体的な名前や交通手段を指定してください。経路検索の「藤が丘」は、`--subway` で地下鉄駅に絞れます。

日種を自動選択できない場合は、`--day` を指定してください。市バスは `weekday`、`saturday`、`holiday`、地下鉄は `weekday`、`holiday`、`new-year`、`all-night` を指定できます。特別ダイヤを指定する場合は、対象の日に適用されることを確認してください。

## 通信とAPIのエラー

`network_error` は接続失敗などの通信エラーです。接続状況を確認し、必要に応じて `--timeout` を増やしてください。`http_error` は取得先が返したHTTPエラーを示します。一時的な障害の場合は、時間を置いて再実行してください。HTTP 502・503・504は自動再試行の対象です。

`invalid_response` と `parse_error` は、想定外の本文や解析できないデータを示します。HTMLが返された場合や、形式の変更、データの破損などが考えられます。`--verbose` で診断を確認し、`--raw` で取得済みの本文を確認できます。`--json` と `--raw` は同時指定できないため、別の実行で指定してください。

`upstream_error` は、API内部のエラーを示します。返されたメッセージを確認してください。

`cache_error` は、永続キャッシュを利用できないことを示します。`--no-cache` を指定すると、キャッシュの読み書きを無効にして再実行できます。

## 0件の結果と不完全な結果

有効な条件で結果が0件になった場合は、成功として扱います。取得に失敗した場合とは区別し、終了コードとJSONの `complete` を確認してください。部分失敗では取得できたデータを保持しますが、`complete: false` と非0の終了コードを返します。再取得に失敗しても、古いキャッシュへ戻ることはありません。

接近情報と次発案内を読む際は、情報の種類も確認してください。市バスの接近情報は取得した現在位置と通過履歴であり、到着予測ではありません。地下鉄の次発は時刻表に基づく予定列車であり、実際の列車位置を示しません。現在位置が取得できない場合も、通過履歴から位置や遅延を推定しません。
